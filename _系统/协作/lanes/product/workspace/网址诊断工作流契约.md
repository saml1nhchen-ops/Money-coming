# 网址诊断与逐题模型表现：产品范围和验收契约

状态：分支 url-diagnosis-flow。2026-10-21 产品已读取最终独立报告与证据，本轮受控功能验收通过，GEO-URL-01独立关闭。真实Cremo访问403、真实模型缺凭据仍受阻；旧团队建制结论未代替本轮功能验收。最终范围见《网址工作流交付摘要》。

## 用户目标与可交付范围

用户输入一个网址即可开始检查，得到有证据的网页诊断、可核对的品牌信息；有已配置模型时继续现有自动出题→同题多模型采样→报告流程。每道问题以独立 box 展示，点击后在 dialog 中比较每个所选模型的提及、引用、完整回答及失败或未运行状态。

无需先填写品牌才能检查网页。提取的品牌是可编辑候选，不能把域名猜测当作已确认事实。网页诊断与 AI 回答表现分别呈现，页面准备度规则分不能称为 AI 可见度评分。未配置模型时网页检查仍可用，AI 流程明确提示连接模型；没有凭据不宣称真实多模型跑通。

当前云端无模型凭据，真实站点 URL 待用户回复。主协调者可用明确标注的确定性 fixture 做 HTTP 与真实浏览器集成；fixture 不进入普通用户默认流程，不冒充真实模型回答或真实网站结果。

## 新增网页检查接口

`POST /api/geo/inspect`，复用 8772 的 Bearer/同源验证。输入：

```json
{"website":"https://example.com","market":"CN"}
```

market 接受 CN/US。前端可补全缺失的 https://，后端按既有公开 HTTP(S) URL 校验，不允许凭据 URL、私网/回环、非允许端口、危险跳转或超限内容。失败沿用 `{error:string}` 和非 2xx，不生成成功分数，不泄露响应/凭据。网页抓取与后续自动出题均继续使用现有安全限制。

200 响应契约：

```json
{
  "website":{"url":"https://example.com/","captured_at":"ISO8601","content_sha256":"hash","bytes":1000},
  "brand":{"name":"Example","aliases":["Example"],"source":"og:site_name","needs_confirmation":true},
  "diagnosis":{
    "scope":"website_readiness",
    "score":75,
    "checks":[{"id":"title","label":"页面标题","status":"pass","evidence":"Example — …","action":""}],
    "methodology":"说明逐项规则、权重、unknown 与计分范围"
  },
  "context":"从真实网页提取且有长度上限的业务背景",
  "warnings":[]
}
```

字段类型固定：score 为 0–100 数值或 null；checks 为数组，status 为 pass/fail/unknown；evidence/action 为字符串；methodology 为字符串；aliases/warnings 为字符串数组。checks 至少覆盖 title、meta_description、h1、readable_text，固定规则与权重由后端在 methodology 写明并测试，不能模型主观打分。unknown 存在导致证据不足时 score 必须 null；已成功获取网页但某已检查元素缺失可为 fail，不混同抓取未知。网页得分的名称固定为“网页准备度”，明确只检查本页，不是全站 SEO 或 AI 推荐效果。

brand.source 标记真实提取来源；候选始终允许编辑。无可信品牌元信息可返回域名候选且 needs_confirmation=true，并警示待确认；不能凭猜测补产品、竞品、用户需求或模型评分。用户确认后的品牌写入现有 brand_aliases；context 预填不得覆盖用户已编辑的补充背景。

接口不调用模型、不配置密钥、不依赖可用模型列表，不自动开始付费采样。配置模型后复用现有 plan/start/sample/run/resume/stop，不破坏已有导出、历史任务及重分析语义。默认题数继续现有30，手工题目保持兼容。

后端已确认具体规则：title、meta_description、h1、readable_text 四项各25分；HTML 可检查项缺失为 fail。可读正文不足100字符或纯文本结构项 unknown 时总分 null 并说明原因。品牌优先 og:site_name、JSON-LD Organization/Brand/WebSite，其次 title，再域名候选；title/域名候选必须 needs_confirmation=true。抓取失败返回400 `{error}`，不合成诊断。

## 逐题卡片与下钻契约

以 job.prompts 为全集，不以已返回 samples 或 report.samples 为题目全集。question_index 为题库零基索引；provider 使用 config.providers 中完整 ID（包括 direct: 前缀）；显示模型名优先冻结 config.configuration 对应 model，回退提供商 ID。旧任务字段缺失时显示未记录，不能伪造模型名。

所有已生成题目包括零回答、运行中、失败及停止的题目都显示独立可点击卡片。卡片展示题目文本/序号、题型（discovery/brand/comparison）、已返回/选中模型数及状态；题面有跟踪品牌/SKU/竞品时明确不纳入自然发现分母。生成阶段尚无题目时展示生成状态，不捏造30道题。

dialog 每个 config.providers 的模型都有独立一栏：

- 回答状态：完整、失败、等待中或未运行。无 sample 且任务 queued/running 时标等待中；任务停止/结束/中断且无 sample 时标未运行，blocked_models 原因可附注。失败 sample 显示实际错误；不把失败、未返回或未运行算零分。
- 品牌提及：完整回答且 analysis 可用时，按 own entity 的 alias 显示已提及/未提及；analysis 不存在则未知。显示明确列表位置及原文依据，没有位置显示未给出。
- 引用：citation、retrieved_source、answer_link 分开标注；不能把官网抓取或普通链接称为 AI 原生引用。完整回答中空引用数组表示未返回引用；analysis 不可用表示未知。
- 原始回答和错误、请求/返回模型信息、计分资格与题型可核对；不完整回答即使有文本也必须标明状态。

优先采用 report.samples 的已有 analysis，回退 job.samples 时保留回答和状态，但不在前端另造一套有偏差的分析。重复采样旧任务按 repeat 保留各条证据，不混入别题、别模型或只挑最好回答。键盘可打开和关闭 dialog，Escape/关闭按钮可用，焦点进入弹窗并回到触发卡片；移动端不横向溢出。所有题目、回答、错误与页面元信息转义，外链限制 HTTP(S)。

## 本轮验收门槛

1. URL-only：不填品牌即可触发真实 HTTP 网页检查；展示品牌候选、真实网页证据、方法及网页准备度；可确认/编辑品牌。无模型凭据时该路径仍成功，AI 状态诚实说明。
2. HTTP：inspect 成功、抓取错误、无品牌元信息、未知检查项、安全 URL 拒绝场景覆盖；无凭据不触发付费调用。既有模型工作流和历史 JSON 保持兼容。
3. 确定性集成：主协调者 fixture 覆盖多个模型、完整命中/完整零命中、失败、缺失样本、品牌词/比较题、原生引用与普通链接、异常文本。通过实际 HTTP 路由获取任务，实际浏览器看到每题一个 box，逐个点击核对完整模型集合和状态，不仅做 VM 字符串断言。
4. 交互：桌面和移动视口、按钮点击、Escape、焦点恢复及长回答可读性有浏览器截图/结果证据。浏览器不可用属于本轮未完成/受阻，不以配置验收代替。
5. 回归：前端适用 CJS、JS 语法和后端 Python 测试通过；unknown/null、零值、品牌词分母、引用类别、导出/重分析原语义不回退。
6. 真实站点/模型：收到用户 URL 后尽可能做真实网页检查；真实多模型调用依赖凭据及可达服务，未提供就明确受阻。确定性集成通过不能称真实模型全链路通过，不编造调用结果；线上发布独立说明。

前后端分别交付 changed_files/output_paths、verification、risks、next_action、acceptance_needed。产品读取两侧交付并确认接口一致后才通知验收独立执行；阻断问题路由责任岗位返修并复验。
