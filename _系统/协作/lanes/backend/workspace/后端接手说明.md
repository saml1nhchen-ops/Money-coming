# 后端接手说明

记录日期：2026-10-21。分支：`geo-agent-team`。本轮为团队建制接手，只读检查业务代码，不实现新功能、不改依赖、不提交或发布。本文为岗位交接材料，供产品汇总和验收复核。

## 代码与运行入口

| 文件 / 服务 | 职责 | 本机端口与存储 |
|---|---|---|
| `server.py` | 旧工作区、回答导入、事实审批、内容版本、实施回执与复测计划 | 127.0.0.1:8765；`work/signal.db` 的 state 表保存整份 JSON |
| `tools/geo_flow.py` | 当前官网→出题→同题采样→确定性报告编排 | 127.0.0.1:8772；`runtime/geo-flows/<id>/flow.json` 与调用导出 |
| `tools/bai_service.py` | B.AI 模型发现、固定模型配置与执行 | 127.0.0.1:8771；`runtime/bai-runs/<id>/` |
| `tools/native_service.py` | 原生开源工具任务、MCP 适配、直连 API 的 HTTP 入口 | 127.0.0.1:8770；`runtime/jobs/`，直连记录在 `runtime/ai-api-runs/` |
| `tools/ai_api.py` | 直连提供商配置、请求/响应适配、精确提及判定、证据落盘 | 由 native_service 调用，无独立 HTTP 服务 |

当前 Windows 入口 `start-signal.ps1` 顺序确保 8770、8771、8772 三个服务存在，打开 8772 research 页；端口已有进程时保留进程和密钥会话。`python3 server.py` 只启动旧 8765 服务。各服务提供相同 dist 静态资源，但 API 范围不同，不能交换端口使用。

当前环境实测 Python 3.12.14、Node v24.19.0；NiubiGEO 的本地 tsx 存在，真实本地 build/parse 测试通过。README 的早期“Python 3.9+”与 QUICKSTART 的“3.10+”不足以覆盖当前实现：`ai_api.stamp()` 使用 Python 3.11 起提供的 `datetime.UTC`，部署须至少核对 Python 3.11+。主服务使用 Python 标准库；自动出题还需要 Node、固定上游 NiubiGEO 和 tsx，其它原生操作分别依赖已安装的 venv、Node 工具或外部服务。仓库导出不包含完整 runtime 依赖。

## HTTP 接口与鉴权

| 服务 | 读取接口 | 写入接口 |
|---|---|---|
| 8765 | GET `/api/bootstrap` | POST `/api/seed`、`/api/action` |
| 8772 | GET `/api/geo/session`、`state`、`run?id=...`、`export?id=...` | POST `/api/geo/start`、`sample`、`analyze`、`plan`、`resume`、`stop` |
| 8771 | GET `/api/bai/session`、`state`、`runs`、`run?id=...`、`export?id=...` | POST `/api/bai/connect`、`profile`、`run`、`clear` |
| 8770 | GET `/api/tools/session`、`health`、`jobs`、`job?id=...`、`bundle?id=...`、`file?id=...&path=...`；`/api/tools/ai/providers`、`runs`、`run?id=...`、`export?id=...` | POST `/api/tools/run`、`/api/tools/ai/configure`、`/api/tools/ai/run` |

表中同一前缀后列出的短路径均继承该行前缀。除 session 外，8770/8771/8772 API 使用进程内随机 token 的 `Authorization: Bearer ...`。session 要求本机 Host 和 `Sec-Fetch-Site: same-origin`。8772 还检查固定 Host 与同源 Origin；8770/8771 允许无 Origin、本机页及代码中固定 Sites 来源，并不等于任意站点开放。8770 实现 OPTIONS/CORS；8771 不提供对应 OPTIONS 处理，不能仅凭 allow-origin 推断跨源写入可用。8765 写入要求固定本机 Host/Origin，无账号 token。

旧 action 请求形状为 `{revision, workspace, action, payload}`，事务通过 `BEGIN IMMEDIATE` 更新 state；revision 冲突返回 409。业务校验失败主要返回 400 + `{error}`。旧服务请求上限 8 MB；8772 上限 256 KB；B.AI/直连上限 512 KB；原生工具任务上限 8 MB。当前异步 start/sample/resume/run 通常返回 202，重新分析返回 201；前端继续轮询任务。

## 当前诊断数据流与前后端契约

1. `dist/research.js` 从 `/api/geo/session` 配对；`geoPayload()` 发送 `market`（CN/US）、`website`、`brand_aliases`、`skus`、`competitors`、`context`、`focus`、`count`、`repeats:1`、`generator`、`providers`、`prompts`。SKU/竞品各含 name、aliases，竞品可含 domains。旧 8765 使用小写 cn/us，不能混用。
2. `catalog()` 经 8771 与 8770 的会话桥汇总已配置模型；直连模型加 `direct:` 前缀。品牌别名 1–20 个；SKU/竞品各最多 30 行；自动题数 1–300；厂商 1–16；新任务每题一次，每厂商固定一个模型，聚合与直连同厂商不可重复计入。手工题集要求 1–300 道、每道不超 4000 字符且归一化后不重复。
3. 自动 start 先校验、规划并落盘；单 worker + BUSY 限制同一流程并发。公开官网抓取限制 HTTP(S)、公开 IP、80/443、最多 5 次跳转、2 MB、18k 可读字符。失败时有业务 context 才继续，否则在模型调用前失败。官网文本是出题背景，不是可见度证据。
4. 固定 NiubiGEO 构建生成 prompt，模型按每 10 题批次生成，再用本地桥解析和去重；题数不足即失败并保留现有题目，不偷偷补题。默认 30 题、一个回答模型的计划最多 33 次调用（3 次出题 + 30 次采样）。`generate_only` 仍会付费调用出题模型，`plan` 不调用模型但需校验配置。
5. 冻结 prompts/hash 后按模型与题目逐个提交给 8771 或 8770；底层单批接口允许 1–10 题、最多 64 次调用。调用记录保留 runner_id、question_index、repeat 等恢复检查点；原始 API 响应以 hash 和文件名关联。429、权限、余额等错误阻断该模型余下题目；无自动重试或自动换模型。
6. job 提供 `id/status/stage/config/prompts/calls/samples/report/plan/planned_max_calls` 等字段。流程状态为 queued/running/finished/partial/failed/stopped/interrupted；阶段为 queued/website/generating/sampling/report。前端约每 2.5 秒轮询活动任务；仅 `status=complete` 的回答可进入相应有效分母。runner 的 `finished` 只表示批次处理结束，仍须检查样本状态，不能直接算全成功。
7. `tools/geo_analysis.py` 生成 `report.samples/models/groups/dimensions/stability/coverage/gaps/sources/methodology`；每份 sample 附 analysis，保留来源到回答的关联。groups 区分 discovery/brand/comparison。发现题分母排除题面点名任意跟踪品牌/竞品/SKU及不完整回答；score 为精确别名命中比例，不是推荐率。无分母 score 为 null，未观察到明确排名 average_rank 为 null；有有效分母且零命中才为 0。
8. 排名仅提取明确编号条目首部并保留依据，普通正文提及不继承条目序号；引用区分 citation、retrieved_source、answer_link。竞品缺口需有效发现回答且本品牌既无提及也无自有平台引用，同时竞品有提及/平台引用。sources 按域名与 kind 聚合并对回答去重，但底层来源包含全部样本，报告 UI 仍需依其展示口径筛选有效发现回答。
9. stop 只停止后续调用，已提交调用会完成并保留费用与证据。重启把运行任务标成 interrupted，不自动重新请求。resume 核对题库 hash、模型配置，先核对未入账调用，再继续缺失采样；reanalyze 从已结束且有样本的任务复制新任务，仅更新品牌/SKU/竞品分析配置，不调用模型且保留原始任务。

`dist/bai.js`、`dist/ai-api.js`、`dist/tool-center.js` 分别使用其独立执行器的会话与接口；8772 不接收密钥配置。跨前后端改变字段、枚举、null 语义、市场大小写、端口、计分分母或引用类别之前，应由产品明确契约与修改归属。公共 fixture 不在本轮可写范围。

## 旧服务与原生工具边界

旧 `server.py` 对象动作约束 workspace，导入按内容/条件 fingerprint 去重，最多 5000 行；新问题保留版本历史。事实批准后才可生成绑定来源的模板草稿，提交审核/批准时检查事实原句；内容或 target 修改撤销批准，批准绑定正文/目标/事实 hash。实施回执只记录人工依据，verification=unverified。复测计划冻结 baseline ID，不自动实施复测。此处 local-user 审批不是多人角色权限。

原生任务按锁定上游和 operation 白名单构造命令数组，非 shell 字符串。任务目录保留 stdout/stderr、退出码、源版本/服务来源、文件 hash；文件下载限制在任务目录内。`bundle` 只接受成功任务，将原生证据转为 v0.1 包，六维规则全部保留 unknown，不把原工具分数转换成 Signal 分数。skill 操作是提供材料内的模型分析，不宣称原生 CLI 已运行；MCP/external service 的来源与固定源码执行不同。health 中 downloaded、native_installed、service-required、skills-loaded 不能视为完整能力验收。

## 凭据与部署限制

- 直连 CONFIG、B.AI KEY/PROFILES 与会话 token 仅保留进程内存；重启需重配。配置公开接口排除 key；任务与原始响应进行已知密钥替换脱敏。原生操作 keys 请求作用于子进程环境，产物做文本脱敏。这些措施尚不能代替完整生产安全审计。
- 当前是本机单用户开发服务。没有服务端身份登录、组织授权、完整租户 ACL、生产队列/预算账本或不可变审计；文件存储和内存 BUSY/POOL 无跨进程持久队列语义。不得直接改绑公网或把 token 配对当作生产身份体系。
- 实时调用依赖账户授权、可用余额、厂商协议、公开网络与各自运行环境。本轮没有测试真实模型响应、实时抓取、付费原生任务、MCP 服务或线上部署；47 项通过不能证明这些链路全部可用。
- 当前 cloud 为受限网络；本轮未进行外部网络请求或安装。GitHub 分支/推送与现有 Sites 发布独立，未验证自动发布，也没有线上变更。
