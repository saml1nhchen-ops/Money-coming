# 在线共享分析后台

GitHub Pages 运行网页；Python 容器运行分析。两人打开同一个网页，填写同一个 HTTPS 后台地址，使用共享工作区密码登录，即可查看同一批任务、报告和证据。不需要各自配置 B.AI 密钥，也不需要保持个人电脑开机。

这是团队共享空间，登录者都能查看、导出和停止团队任务，不提供成员独立的数据隔离。

## 已准备的部署方式

- `Dockerfile`：Node 22、Python 3、固定版本的分析依赖，非 root 运行。
- `render.yaml`：新加坡单实例后台和持久磁盘；创建服务属于付费操作，尚未创建，也未开通自动部署。
- `compose.yaml`：可迁移到阿里云、腾讯云等 Linux 主机。默认仅向本机开放 8080，公网需要 HTTPS 反向代理。

Render 操作：用 GitHub 登录 Render，创建 Blueprint，选择此仓库的 `cremo-online-connection` 分支，审阅服务和磁盘报价后再创建。在服务的密钥设置中填写：

| 变量 | 内容 |
| --- | --- |
| `SIGNAL_BAI_API_KEY` | 你的 B.AI 密钥；不要写入网页、Git 或聊天 |
| `SIGNAL_WORKSPACE_PASSWORD` | 至少 16 个字符的团队登录密码，与 B.AI 密钥不同 |
| `SIGNAL_DAILY_CALL_LIMIT` | 每天允许预留的模型调用次数，默认 126，0 停止新增付费任务 |
| `SIGNAL_GPT_MODEL`、`SIGNAL_GEMINI_MODEL` | 可选，必须是 B.AI 实时目录中存在的固定模型 ID |

Render 自动提供公开主机名。其他主机还需设置 `SIGNAL_PUBLIC_HOST`，例如 `api.example.com`，并配置 TLS。只运行一个实例，持久挂载 `/app/runtime`；升级前备份此目录，包含任务证据和调用预算账本。

启动命令：`python3 tools/remote_service.py`。容器只公开 8080；8770、8771、8772 保持容器内回环访问。匿名 `/healthz` 仅报告服务存活，模型可用性需要登录后查看。

部署完成后，在网页“分析与报告”的在线后台连接区填入服务的 HTTPS 地址，使用团队密码登录。浏览器只保存后台地址，登录凭证仅在内存中，有效期一小时；刷新需要重新登录。

## Cremo 验证

1. 确认后台显示已连接、B.AI 模型目录已获取、两个固定模型可选。
2. 输入 `https://cremocompany.com`，市场选美国，确认网页识别的品牌信息。
3. 点击生成并分析，确认 30 个问题、每个模型一次回答。生成阶段最多预留 3 次调用，双模型回答最多 60 次。
4. 检查每个问题有独立卡片，打开弹窗查看各模型回答、品牌提及、引用和失败状态。
5. 检查报告先呈现总分/覆盖情况和主要结论，再呈现竞品差距、引用证据和行动。缺失证据不能被算成肯定结论。
6. 合伙人登录同一后台后，确认看到同一任务并能导出证据。

调用前按最坏情况扣减当天 UTC 的调用配额。失败、停止和结果不明确的任务不返还额度，避免重试造成超额收费。这是次数上限，不是金额上限，具体费用取决于所选模型及 B.AI 计价。没有自动付费重试。

## 发布和迁移

本配置不把创建 GitHub Release 等同于部署成功。Render 自动部署暂时关闭；先验收目标提交，再手动部署。若以后接 Release 自动发布，应在有实际托管账号后接入受保护的发布流程，并验证部署结果。

迁移时保留域名、密钥设置和 `/app/runtime` 数据，将域名 DNS 指向新后台；网页无需更换域名。备份不得进入公开仓库。

## 当前外部阻塞

本云环境尚无已绑定的 B.AI 密钥或托管账号，生效的网络策略也没有开放 B.AI 和 Cremo 域名。因此本地测试不代表已获得 Cremo 真实模型评分；不得用测试样本替代正式结果。
