# 腾讯云香港：共享在线后台

用途：你和合伙人分别登录同一后台，共用服务器上的 B.AI 连接、任务和报告。每台设备无需输入模型密钥。团队密码用于访问保护，不是 B.AI 密钥。后台运行不依赖个人电脑在线。

## 购买前

部署会话已确认当前香港后台及 v0.3.1 自动部署成功。以下是新主机的安装参考；建议在腾讯云轻量应用服务器选择：**香港、Ubuntu 24.04 LTS、x86_64、2 核 4 GB、至少 40 GB 磁盘**，或选含 Docker 的应用镜像。小规模两人使用从单实例开始；固定套餐、流量包、续费价与税费以购买页为准，B.AI 调用另计。不要购买 Windows、只读静态托管或多实例。

控制台：<https://console.cloud.tencent.com/lighthouse/instance/index>

防火墙只开放 80/TCP、443/TCP（可选 443/UDP）和你管理来源的 SSH 端口。**不开放 8080、8770、8771、8772**。后台容器不映射公网端口，由 Caddy 提供 HTTPS。

## HTTPS 与域名

正式使用建议使用自己域名的子域，例如 `api.example.com`，DNS A 记录指向服务器公网 IP，IPv6 未配置时不要添加 AAAA。香港服务器不需要中国内地服务器的 ICP 接入备案流程；域名注册商可能仍要求实名。

暂不购买域名时，可在得到公网 IP 后尝试 `<IP>.sslip.io` 等临时解析域名并实际验证 Caddy 能取得证书。这依赖第三方 DNS 和证书签发额度，不保证成功或长期可用；不要把 HTTP 裸 IP 或自签名证书接给 HTTPS GitHub Pages。

## 服务器配置

先通过云控制台安装 Docker Engine 与 Compose 插件。将仓库拉到服务器上的固定目录：

```sh
git clone https://github.com/saml1nhchen-ops/Money-coming.git
cd Money-coming
bash deploy/configure-team.sh
docker compose up -d --build
docker compose ps
```

配置脚本在服务器终端隐藏输入 B.AI 密钥和至少 16 字符的团队密码，写入权限为 600 的 `.env`，不会打印密钥或加入 Git。后台读取真实模型目录，选固定 GPT 与 Gemini 各一个；如果需要指定版本，在服务器 `.env` 中设置实际存在的 `SIGNAL_GPT_MODEL` 与 `SIGNAL_GEMINI_MODEL`。保存不代表余额、协议或付费调用验证通过。目录失败会显示未就绪，不自动重试付费请求。

v0.5.1起，目录提供固定Claude聊天型号时会增加一个可选连接，优先Haiku系列；v0.5.2起可全选实际可用连接。可用`SIGNAL_CLAUDE_MODEL`指定目录中的固定型号，错误配置会明确报告；未配置且目录没有Claude时保留原两家。网页会员资格不等于API免费。`healthz.capabilities.claude_available`仅表示实际已配置Claude，不代表已经执行聊天调用或核实价格。

每日默认 126 次保守调用预约，30题首次按3+30×模型数预约：双模型63次、三模型93次；沿用已保存题集的三模型复测预约90次。次数不是金额上限；失败和停止不自动返还，调整 `SIGNAL_DAILY_CALL_LIMIT` 后重启后台生效。密钥只进后台内存与服务器私有配置，不给浏览器返回。

如果服务器配置了通用 HTTP/HTTPS 出网代理，官网抓取会停止，防止代理二次解析绕过内网保护；不会绕过代理直连。仍可填写品牌背景继续模型问答，抓取失败不生成官网分数。

## 两人使用

1. 打开默认网站或 `dist/team.html#/w/demo/research`；后台地址已预填为 `https://43.154.242.184.sslip.io`，无需每台设备再配置模型密钥。
2. 首次用团队密码登录，默认勾选“在此设备保持登录”；公共电脑可取消。中国、美国市场各自选择模型并分析。
3. 两人可查看同一批报告、导出和停止任务。没有成员级数据隔离；不要把团队密码分享给无关人。

保持登录只在这台设备保存该后台的登录凭证与到期时间，不保存团队密码或 B.AI 密钥。支持新协议的后台签发 30 天凭证，刷新、重新打开以及后台重启后可恢复；主动退出、到期或修改服务器团队密码后需要重新登录。未勾选时只保留当前页面的 1 小时会话。旧后台未发布新版本时，前端兼容其原协议，最多记住原 1 小时会话，后台重启仍会失效。

恢复登录只读取状态和历史，不自动开始模型分析。网络故障会保留未过期凭证并停用开始按钮；身份验证失败才要求重新登录。浏览器清理网站数据或禁用存储会影响保持登录。不要在公共设备保持登录。

## 验收与运维

- `https://后台域名/healthz` 应包含 `"ok":true`；新后台的持久会话库可用时还包含 `capabilities.remember_login:true`。匿名访问 `/api/geo/state` 必须拒绝。
- 在团队页登录后应显示真实完整模型 ID、双市场、每日预算与共享任务。用两台设备登录查看同一报告。
- 后台数据在 `signal-geo-runtime` 持久卷；容器重启后保留报告、预算及新协议的设备会话库 `runtime/device-sessions.sqlite3`。该库只存令牌摘要，备份仍应保密。旧的 1 小时内存会话重启失效；中断任务不自动续跑。
- 在模型目录成功并明确点击开始前，不代表已完成 Cremo 真实分析；模拟测试不能作正式分数。
- 更新先确认无分析运行，备份 runtime，再在服务器拉取已验收提交并 `docker compose up -d --build`。不要执行 `docker compose down -v`，它会删除数据。
- 已核对 v0.3.1 正式 Release 自动部署成功，30 天保持登录已包含在服务器镜像中。原短期登录不会自动延长，首次重新登录时保持默认勾选以取得新凭证。详见 [Release 部署](RELEASE.zh-CN.md)。只有 GitHub 提交不代表腾讯云后台已更新。

页面保存过的自定义后台地址会优先于部署配置。可打开 [连接修复入口](https://saml1nhchen-ops.github.io/Money-coming/dist/team.html?reset_backend=1#/w/demo/research)，只恢复到代码中已配置的正式后台地址；不会从网址读取任意服务器、密码或令牌。目标已有设备凭证则仅验证状态，否则只做一次匿名健康检查，不自动登录或开始收费分析。普通自定义后台选择继续保留。修复参数处理后从地址栏移除，其他草稿参数和路由保留。

## 迁移

保留域名与 DNS 管理权。停新任务，备份持久卷和服务器私有 `.env`，在新服务器恢复同一个 Docker/Compose 应用和卷，验证后把域名指向新 IP。备份含报告与密钥，不能放公开仓库。TLS 证书由新服务器重新申请。阿里云香港 Linux 主机可使用同一套配置。
