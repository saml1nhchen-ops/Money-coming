# 官网检测

团队工作台输入官网时，现有识别请求同时返回官网检测结果。不额外调用模型，不自动启动 30 题分析。检测反映腾讯云后台本次访问情况，不等同于用户浏览器能否打开。

检测范围：公开地址校验、域名解析、HTTPS 证书验证、HTTP 状态、逐跳跳转链、内容类型、大小和可读字数。HTTP 429 表示限流；403 表示拒绝访问，两者均不能独自证明反爬。符合组合特征的验证码/访问挑战页显示‘疑似验证页面’，不当作品牌或产品证据。失败时保留手工填写，不自动反复请求，也不破解验证码。

继续使用现有 DNS 地址固定与逐跳公开地址验证，保留 TLS 校验和 2MB 上限；不运行网站脚本。检测只面向当前官网页面，未检查 robots、站点地图、整站 SEO 或生成 GEO 分数。

## GitHub 工具调研

- [Crawlee](https://github.com/apify/crawlee)：抓取任务、队列、并发与浏览器抓取流程。适合后续多页面采集。
- [Playwright](https://github.com/microsoft/playwright)：浏览器自动化与页面渲染。适合后续确实依赖 JavaScript 的页面，也已用于本项目前端测试。
- [Trafilatura](https://github.com/adbar/trafilatura)：正文和元数据提取。适合后续提高内容提取质量。

本轮查阅以上仓库 README，未将这些工具新增到生产读取链路。当前问题首先需要可靠地区分访问失败原因；直接加入浏览器或爬虫框架不能保证解除限流，而且会增加内存与维护负担。

## 本轮验证

163 项 Python 检查通过，独立验收覆盖 13 项识别、12 项原网站安全、10 项检测，以及两套 Chromium 页面测试。覆盖 429/403、DNS 空结果、证书失败、跳转限制、私网拒绝、正文不足、HTTP 200 挑战页及诊断转义。实际 Python 3.11 容器验证了异步接口初始化、结构化安全拒绝、结果保存及零模型调用。合成用例不等于特定官网实测。
