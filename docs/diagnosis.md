# 官网自动诊断与评分

在“诊断与评分”页点击“从官网生成诊断”，填写官网、品牌名称、别名和目标市场即可开始。可以选择关联一次已完成的品牌分析任务。后台通常需要 1–2 分钟生成 v0.1 证据包；完成后自动打开报告，并在“历史诊断”中保留。整个过程不调用模型，不产生模型费用。

## 流程

1. **采集**（`tools/geo_diagnose.py`）：抓取首页，再按导航链接和站点地图选取代表页，包括关于、产品/服务、FAQ、联系、文章，总共最多 8 页；同时读取 robots.txt 和站点地图。复用官网识别的安全约束：只访问公网地址，DNS 结果固定，TLS 校验不关闭，逐跳检查重定向，单个响应不超过 2 MB，不执行 JavaScript。服务器配置了通用出网代理时停止抓取，不绕过代理。
2. **判定**：按 `tools/diagnostic_rules.json`（`signal-rules-v1`）的 27 条规则逐条判定，覆盖六个维度，权重为 25/20/20/15/10/10。每条规则都记录判定原因、引用的证据和目标页面。证据无法判定的规则保留为 `unknown`，不按零分处理。部分满足统一按 0.5 计分。
3. **回答**（可选）：关联品牌分析任务后，任务中的回答会按 v0.1 格式转为 `answers`，用于判定 R-Q3（无品牌提问中的提及率）和 R-Q4（引用自有网站的比例）。不关联时这两条规则为 `unknown`，页面只显示分数区间。
4. **问题清单**：未满足和部分满足的规则自动生成问题条目，附带证据、建议动作、负责方、工作量和复核方法；`unknown` 规则生成“待验证”条目。
5. **存储**：结果保存在后台 `runtime/diagnostics/<id>/job.json`，Docker 部署时位于持久卷内。同一时间只运行一个诊断；后台重启时，未完成的诊断标记为“已中断”，不会自动重跑。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/geo/diagnose` | `{website, market: CN/US, brand, aliases?, flow_id?}`，返回 202 |
| GET | `/api/geo/diagnoses` | 最近 50 次诊断 |
| GET | `/api/geo/diagnosis?id=` | 单次诊断及其证据包 |

团队网关需要登录。诊断不读取模型配置，也不占用每日调用预算；后台维护期间拒绝新的诊断请求。

## 边界

- 规则和阈值是暂定产品规则，不是平台排名权重，可以随客户实践调整。修改规则时要同时提高 `version`，复测对比会提示规则版本不一致。
- 抽样页面有限。“未找到关于页”这类结论只代表在首页链接和站点地图中没有找到，报告的“其他解释”中写明了这一点。
- 关键词类判定（例如认证、奖项表述）只说明页面上出现了相关字样，不能证明信息真实，需要人工核对。
- 目前还不能在网页里人工改判规则。需要改判时，导出 JSON，修改后通过“导入证据包”重新载入。

## 验证

`python -m unittest tests.test_geo_diagnose tests.test_remote_gateway` 使用离线的模拟网站，覆盖页面发现、规则判定、证据引用、首页不可达、关联回答以及前端校验器验收。另外在本地连通了团队页 → 网关 → 8772 的完整流程，并用浏览器截图检查。没有对真实官网做实测：当前开发环境的出网代理会触发安全拒绝。
