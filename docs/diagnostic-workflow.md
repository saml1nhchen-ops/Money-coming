# 持久诊断与客户报告

## 已批准的产品边界

官网识别完成后由用户核对品牌、产品和竞品，再明确选择模型并确认30道问题的调用范围。官网规则诊断与模型表现一起生成报告，但不把两套评分直接相加。网站规则未知时展示分数区间和覆盖率；提及、推荐、引用分别使用有证据的分母。

默认工作台入口保留；历史报告提供固定链接、HTML与JSON下载和打印PDF。主报告先展示结论，再展示竞品差距、官网问题、引用和行动；每题可查看各模型回答。

## 客户及复测

当前团队成员共同管理客户及项目，不开放客户账号。项目保存品牌、市场和题集关联。旧数据归入内部历史项目，不能直接发布客户分享。发布生成独立快照，通过默认30天有效、可撤销链接查看；撤销不删除内部报告。

复测手动触发，保留题目原文、模型及规则版本、页面集合等口径。不同配置不合并趋势。暂不启动定时或无人值守模型调用。

## 实现边界

`tools/geo_diagnose.py`协调现有官网审计及模型流程，版本规则在`tools/diagnostic_rules.json`。报告按既有v0.1证据包持久化到runtime/diagnostics；旧geo-readiness-v1及采样原件保持不变。后台校验项目归属、分享权限、预算和幂等，不依赖前端过滤。

新增模块尽量使用明确的调用接口，避免继续叠加全局render覆盖。HTML/JSON/打印视图必须来自保存的同一份报告，导出不能触发模型采样。

## 发布

数据库变更采用新增结构，保留原运行数据和预算。现有腾讯云Docker卷继续使用，正式Release触发后台升级；Pages仍随main更新，因此前端需明确处理后台尚未具备新接口的状态。线上验收记录实际版本和结果，不以构建成功代替部署成功。
