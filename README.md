## 持久诊断与团队交付

团队页支持“输入官网 → 确认品牌/产品/竞品 → 确认模型与调用范围 → 完整诊断”。官网检查和30题模型回答分别保留证据；未验证的六维规则显示未知和分数区间，不把两套评分相加。报告、历史记录、客户与项目保存在腾讯云后台的持久runtime卷，刷新页面不会丢失已提交任务。

在客户项目中生成的报告可导出完整HTML、JSON或打印PDF；也可创建默认30天、可撤销的只读报告链接。手动复测冻结原题集，比较前检查品牌、市场、规则、页面和实际模型条件。本轮不开定时采样，不创建客户账号；同一团队共管所有客户，客户/项目归属不等于多租户或个人角色授权。旧数据保留在内部历史项目，不自动转换或对外分享。

实现与范围见[持久诊断与客户报告](docs/diagnostic-workflow.md)。部署结果以正式Release工作流和服务器实际版本为准。下面部分说明保留早期本地/离线模块的使用边界，不应据此判断团队新接口是否已经部署。

浏览器直连 B.AI：在原“品牌分析”三步页面同页连接、选择真实固定模型，自动生成 30 道题并展示回答与证据；官网仅作对象标识。用法、费用上限与验证边界见 [直连说明](deploy/BROWSER-DIRECT.zh-CN.md)。

新增“开源工具与执行”：18 个原始仓库固定版本、420 份原始 Skill 文档和许可证、10 组原生 CLI/脚本适配、OpenSEO/Elmo/SE Ranking MCP 适配，以及本机任务日志、原生文件下载和证据交接。使用 `start-tools.ps1` 启动本机执行服务。完整能力、已验证路径与缺失环境见 [tools/INTEGRATION.md](tools/INTEGRATION.md)。完整应用栈、账号登录和所有付费实时采样尚未运行，不能将“源码已导入”视为“全部功能已上线”。

## 2026-10-19 诊断方案更新

已按《GEO诊断与评分报告Skill_设计方案》v0.1 增加离线诊断入口。网站实现证据包验收、规则计算、可展开报告及复测配置对比；没有创建或安装独立 Codex Skill，也没有接入实时采样或模型判定。

- 首页默认进入诊断与评分；保留原有观察、内容审核与人工执行模块。
- 在线诊断支持会话内导入 v0.1 JSON 证据包。数据只在浏览器内存中处理，刷新清除；不会提交公共站点或写入原 Demo 回答库。原有普通回答导入仍需本地服务。
- `run_manifest` 定义范围和版本；`rules` 按六维 25/20/20/15/10/10 总计 100 分。未采集的规则须保留为 unknown；N/A 必须提供理由。部分满足必须提供预定义部分得分及 rubric。
- 适用权重 A、已得分 P、未知权重 U：下界 100P/A，上界 100(P+U)/A，覆盖 (A-U)/A。U>0 时不显示正式单一总分；A=0 无法评分。
- `answers` 按实际平台、入口、市场、语言、题型分别计算；仅完整可观察的原生引用进入引用率分母。推荐判定未提供时为 unknown。失败、截断和缓存标记不算未提及。
- `evidence` 保存来源、片段位置、hash、时间与完整性声明；`findings` 连接问题、规则、证据与候选改稿。可选 `questions` 数组用于没有回答的页面诊断。导入方须提供可靠判定，站点不自动核验远程 hash 或调用模型验证语义。
- 从规则和行动可展开原始证据；问题覆盖图和引用来源表保留未知项。事实正确率和竞品配对判定尚未实现，明确显示 unknown。
- JSON、HTML、Markdown 报告共享同次计算数据；HTML 可浏览器打印为 PDF。导出的是浏览器生成文件，不包含服务端归档或真实发布时间确认。
- 复测比较版本、实际问题/入口/地区/引用能力、页面与规则配置；变化时列出不一致条件，不生成统一提升比例。相同配置也不构成因果结论。

验证：`node tests/test_frontend.cjs`、`node tests/test_diagnostic.cjs`；浏览器检查首页、平台分母、规则展开和证据抽屉。

## 打开方式

线上站点是独立 Demo：虚构品牌与合成回答，内存操作刷新后重置，不接收真实导入。不要将示例导出当作客户业绩。

真实回答请在本地使用：双击同目录下 `启动 Signal GEO.command`，保持终端打开，在浏览器访问 http://127.0.0.1:8765 。或者在本目录执行：

```sh
python3 server.py
```

无需安装 Python 第三方包。要求 Python 3.9+。服务只绑定本机回环地址，端口固定 8765；按 Ctrl+C 停止。

## 建议体验顺序

1. 进入 Demo，点击指标、图表日期、问题与单次回答，查看原文和引用。
2. 本地左侧切换“我的品牌”，在设置中填品牌、别名和自有域名。Demo 与真实工作区分开。
3. 在导入弹窗下载 JSON 模板，用实际问题、原始回答、采样时间和实际产品模式填写；也支持 CSV。
4. 先校验预览再确认。无效行可下载错误清单；成功行独立导入。原文与采样条件完全一致的记录去重。
5. 查看按市场、模式与日期计算的提及率、引用覆盖及回答证据。失败回答不进入有效分母。
6. 从原回答建立调查项目。添加有来源和适用市场的事实，经人工批准后组装模板草稿。
7. 保存草稿、提交审核、批准精确版本、导出修改包并记录人工实施依据。保存修改自动撤销旧批准。
8. 保存复测计划，冻结当前筛选下的基线回答 ID。当前不运行自动复测、不评估因果提升。

## 与 Word 的差距

- 未完成多人身份登录、服务端角色权限、Agency 客户授权、不可变生产审计及正式多租户安全验收。当前工作区约束不等于完整 ACL。
- 实际分析在浏览器执行；生产统一报告服务、query_id 与服务端冻结报告待建设。目前报告是下载后冻结的 JSON，未建立服务器报告库。
- 尚未实现题目类型配置；本版仅适用于无品牌发现题，导入前需人工筛选。带品牌核实题不可混入本版指标。
- 市场预设为美国/中国大陆，未提供市场新建、城市/商品/门店实体管理与多市场事实有效期校验。
- 无自动采样、计划采样覆盖率、抓取快照、事实模型核查、情绪模型、向量检索、模型生成、CMS、需求量、购物卡或机器人数据。
- 不含自主 Agent、Workflow DAG、任务队列、预算账本、定时任务、复测实际执行及显著性分析。
- 仅原回答抽屉具备详情 URL；题目/内容等详情完整路由、分页、复杂筛选、多语言完整错误文案及未保存输入跨导航恢复待完善。
- Demo 的前端状态操作用于交互预览；正式约束以本地后端为准。不得将此开发服务改绑公网作为生产系统。
